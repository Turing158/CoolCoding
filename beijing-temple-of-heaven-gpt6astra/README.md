# 天坛 · 祈年殿

**天地之间，一座可以走近、旋转和逐层拆解的祈年殿。**

Three.js **r160（`three@0.160.0`）** + Vite，原生 JavaScript ES 模块。所有建筑、植物、瓦片、雕饰、材质贴图和动画均在运行时由代码生成。没有外部模型、图片、字体、HDR 文件或 CDN 请求。首次安装 npm 依赖需要网络；构建产物可离线部署到本地 HTTP 服务。

![祈年殿桌面效果](validation/desktop.jpg)

## 启动

需要 Node.js 20.19+ 或 22.12+，已在 Node.js 24.18.0 下构建。

```powershell
cd D:\EducationalData\project-show\cool-coding\beijing-temple-of-heaven-gpt6astra
npm install
npm run dev
```

打开 **http://127.0.0.1:8132/**。不要直接双击 `index.html`，ES 模块需要 HTTP 服务。

```sh
npm run build       # 生成 dist/ 静态部署文件
npm run preview     # 在 127.0.0.1:8132 预览生产构建
npm run check       # 不启用 WebGL 的几何与动画完整性检查
```

开发与预览使用同一个端口，请择一启动。端口被占用时会明确报错；可通过 `npm run dev -- --port 8133` 更换端口。部署时上传完整的 `dist/`，相对资源路径也适用于子目录。

## 建筑与程序化细节

- **三重曲面琉璃瓦屋顶**：使用非线性曲线采样与 `LatheGeometry`，檐缘有真实反向微翘；592 条自定义瓦垄、滴水瓦头、内侧椽子分别实例化。Canvas 生成瓦片接缝、釉色变化与细小纹理。
- **鎏金宝顶**：多段旋转体塑造宝珠、承座与尖顶，金属材质使用程序化天空环境反射。
- **28 根朱柱**：十二外檐柱、十二内圈柱、四中心柱，配石础、箍圈、柱头和高低不同的承托层。
- **三层斗拱与彩枋**：弧形拱件挤出，纵横相交、逐层出挑；青绿、靛蓝、金色梁枋使用程序绘制的花心、卷云和回纹。
- **圆形殿身与门窗**：十二开间、48 扇隔扇，真实门框与铜钉，程序化菱格格心、裙板及“祈年殿”匾额。
- **三层汉白玉台基**：带收分和线脚的圆形旋转体、环形望柱栏板、四向连续九级石阶；南北中央御路以云龙纹贴图及凹凸表现浅浮雕。
- **天空与广场**：程序化北京蓝天天空、铺砖广场、中央石路与八株柏树；DirectionalLight、HemisphereLight、AmbientLight、缓存软阴影、半分辨率 SSAO、ACES 电影色调映射。

这是基于祈年殿建筑特征的艺术性程序化重现，非测绘级模型。比例和部分构件有利于交互展示的概括，龙纹是代码绘制的抽象纹样；1420 年指建筑始建年份，现有形制经历过明清改建。

## 低负载运行与验证

默认最高 **30 FPS**，关闭自动环绕并停止操作后不再调度帧；隐藏标签页时停止定时器和 RAF，恢复时不会补跑离开期间的动画。阴影只在几何移动、设置变化或尺寸变化时更新。平衡画质像素比上限 1.35，并限制总像素数量；SSAO 使用 12 个采样、半尺寸缓冲，节能模式默认关闭 SSAO。

推荐的有限帧数实测地址：

```text
http://127.0.0.1:8132/?test=1&fps=6&frames=12
```

它以最多 6 FPS 绘制 12 帧，之后**停止调度**。测试面板可以“绘制 1 帧”或“运行 24 帧”。拆解、复位或自动环绕等交互仅开启一批有限帧，因此长动画可能暂停在中途，点“运行 24 帧”即可继续。测试预算耗尽后不会自动恢复常驻循环。窗口尺寸改变仅按需补一帧。

| URL 参数 | 含义 |
| --- | --- |
| `test=1` | 显示诊断面板，并启用有限帧数预算；默认 6 FPS／12 帧 |
| `fps=6` | 1–60 的帧率上限，非法值回退默认值 |
| `frames=12` | 测试初始预算，限制 1–240 帧 |
| `still=1` | 从静态视图开始，自动环绕关闭；交互仍可用 |
| `quality=eco` | `eco`、`balanced`、`high` 画质 |
| `labels=1` | 初始显示建筑标注 |

诊断面板提供真实绘制数、剩余预算、相机位置、拆解进度、实例数、错误与外部资源请求。`frameCpuMilliseconds` 仅测量 JavaScript 提交这一帧的耗时，**不是 GPU 帧时间或稳定帧率证明**。

当前建筑部分包含 **7,098 个实例、70 个实例批次、111 个 Mesh、580,884 个三角形**。三角形数字是建筑几何总量；阴影和环境遮蔽会增加实际提交次数。近景瓦垄保留真实几何，画质预设主要调整像素、阴影与遮蔽开销。

`npm run check` 检查真实建筑几何和动画：三屋顶曲率与翘檐、三台基、28 柱、顶点和法线有限性、分层错峰、途中反向、爆炸高度与 12 次完整往返后的精确矩阵恢复。不会创建 WebGL 上下文。

2026-09-17 已在 Codex 内置浏览器完成生产构建的有限帧数验收，覆盖完整拆解／重组、三种视角、旋转缩放、自动环绕、画质切换与桌面／手机／平板布局。正常模式静止约 40 秒后仍仅绘制 1 帧。截图、运行数据和未验证范围见 [VALIDATION.md](VALIDATION.md)。

## 模块结构

```text
index.html                    展览界面、控件与说明
src/
  main.js                     渲染、相机、控件、画质、可见性与诊断
  config.js                   尺寸、层级、画质与 URL 配置
  temple.js                   建筑装配与统计
  roofs.js                    曲面屋顶、瓦垄、檐口、椽子与宝顶
  timber.js                   柱网、斗拱、殿身、彩枋与门窗
  terraces.js                 汉白玉台基、石阶、栏杆与望柱
  environment.js              广场、绿化、程序化天空与照明
  materials.js                Canvas 纹理及 PBR 材质
  kit.js                      几何工具、实例批处理、资源释放
  motion.js                   可逆错峰动画与按需限帧调度
  style.css / ui.css          自适应界面及面板样式
scripts/check-architecture.mjs 无 WebGL 的结构检查
```

调整屋顶和台基参数优先修改 `config.js`；添加建筑层时用 `layer()` 注册初始位置和展开向量，重复构件交给 `InstanceBatch`，避免在渲染循环内创建几何或材质。
